# tkos.world/0.2 在长期分支上开发，锁版前只留一个可重写的迁移

0.2 的实现要改表结构：迁移 0030 用 CHECK 把 world 事件的种类、阶段与结果限定在 0.1 的取值，绑定门（最近一次定义在 0035）遇到 `tkos.world/0.2` 直接报「未实现」。执行计划又要求第 1 至第 4 步在可清空的实验环境上做，正式迁移与锁版只在第 5 步。我们决定：0.2 在长期分支 `world/0.2` 上开发，锁版前不并入 main；分支上的表结构改动只放在一个迁移文件里，取 main 上下一个未用的编号（当前是 0039），锁版前可以反复重写；实验库每次从头重建（`acceptance/method_v05/database.py` 先 create 再 upgrade），不做增量升级；第 5 步契约与登记定稿后，钉定两者、冻结这个迁移并合入 main，此后回到 append-only。

## Considered Options

- 每改一次契约就追加一个重钉迁移：0.1 开发期间这样做了五次（0031 至 0035）。被否：0.2 在实验结论出来前还会改结构，追加的迁移都会进 main，并随发版进入部署环境。
- 先在 main 上合一个只给 0.2 加绑定分支的迁移：被否。绑定门要钉契约与登记的哈希，契约每改一次就要换，等于提前锁版。

## Consequences

- 锁版前这个迁移只能用于可清空的库：隔离验收栈与新起的实验实例。world-lab、生产实例与 Clark 联动栈（54350/54351）一律不跑。
- 在此期间 main 若有别的改动占了 0039，0.2 合入前改用下一个未用编号；`tests/test_migrations.py` 的文件清单在分支上同步维护。
- 分支要定期合入 main 的改动；逐票的改动先合进 `world/0.2`，第 5 步再由它向 main 开一个 PR。
