# 状态快照由 Agent 或责任人直接写入，无确认门

tkos.method/0.5 的经营状态需要有权责任人确认后才正式。tkos.world 里的状态快照只描述现状（进展、问题、产物链接），由 Agent 或责任人写入即生效，无人确认，历史天然保留；Agent 起草的对象内容作为状态快照里的产物链接存在，只有经承诺与确认写回对象后才成为正式内容。

## Considered Options

- 沿用 0.5 的确认式状态：被否，确认会把描述变成决定，Agent 高频刷新时门会成为瓶颈，且与「事件是唯一触发源」冲突。

## Consequences

- 读侧展示状态快照时必须标明它未经确认；问题（issue）只是状态快照下的块，由 Co-Agent 分流，不产生对象。
- 术语上「状态快照」与 method 的「正式经营状态」分开使用，见 `CONTEXT.md`。
