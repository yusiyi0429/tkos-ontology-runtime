# 业务世界模型以新协议 tkos.world/0.1 承载，tkos.method/0.4、0.5 冻结，内核复用

9/23 CEO 的《企业业务世界建模框架》把对象、门与状态的语义改到了与刚验收的 tkos.method/0.5 不同的形状（Mission 由 Owner 承诺、DRI 确认；状态无人确认；Constraint 降为块；复盘不再是对象）。我们决定不演进 method/0.6，也不重写运行时：新开协议 id `tkos.world`，作为并存协议加入本进程的支持集合；对象存储与修订、协议绑定、激活策略判权、身份与角色指派、证据存储、控制面、读侧框架全部复用；0.4、0.5 原样冻结，验收数据留作回归，不建数据桥、不为统一而改旧语义。

## Considered Options

- 演进为 tkos.method/0.6：被否，门的方向和状态的效力都反了，同名对象含义不同会让契约不可读。
- 大规模重构或重写内核：被否，内核与协议无关且刚过验收，重写只换来重跑全部验收矩阵。

## Consequences

- 同一 scope 里可能同时有 method 与 world 对象，含义由绑定协议决定，读侧必须按协议投影。
- 世界模型的每一次语义变化都以新协议版本发布，而不是改旧版本模块。
