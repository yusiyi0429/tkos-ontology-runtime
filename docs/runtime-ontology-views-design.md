# Runtime 本体可视化设计对齐记录

状态：已由 Kimi Code 开发，Codex 完成审查修复、本地接口与浏览器验收；详见[验收报告](runtime-ontology-views-acceptance.md)。尚未部署新版容器。

## 已确认的决定

- 提供并列的“本体地图”和“业务关系图”视图，支持切换。
- 默认打开“本体地图”。用户在首轮选择了方案 C。
- 两个视图分别表达业务概念结构和真实业务记录关联，术语见根目录 CONTEXT.md。
- 本体地图首屏按五个业务区域分层展示：战略与责任结构、目标与 Mission、共同核对、经营与复盘、战略研究。点击区域展开具体对象；证据、身份与权限作为共同支撑。用户确认 Q2 B。
- 地图保留尚无业务实例的对象类型，不以当前数据有无决定概念是否展示。
- 点击对象类型后，在右侧展示可分段折叠的业务说明卡：定义、主要业务信息、对象关系、生命周期、操作主体及正式效力，并提供查看实际数据的入口。用户确认 Q3 B。
- 业务说明卡解释例如“CEO 确认后的正式 Mission 尚未获得执行授权”的效力边界；技术字段留在现有技术溯源入口。
- 直接进入业务关系图时，默认从一个明确选择的战略展开目标与 Mission，再逐步展开状态、问题和证据；存在多个战略时要求选择。支持以具体对象为中心定位。用户确认 Q4 A。
- 从本体地图点击“查看 Mission 数据”时，先展示当前可见 Mission 列表，选中后定位具体对象的关系图；其他类型采用同样语义。
- 业务关系图默认正式内容优先，主动开启候选或历史比较。正式对象必需的旧版依据始终显示并标注历史依据，不隐藏、不重新挂接。用户确认 Q5 A。
- 本体地图默认最新 0.3，支持切换 0.1/0.2，界面称“业务规则版本”；查看实际对象的规则时自动使用其绑定版本，不套用最新规则。用户确认 Q6 A。

## 已核对的现状

- 当前界面为类型导航、对象列表和单对象详情。
- 详情中以列表展示直接依据、来源材料和下一层对象，没有概念总图或全局实例关系图。
- 当前六组导航未覆盖完整 Method 对象目录。
- 已有精确版本读取和对象邻接查询可以复用；概念结构不能由当前数据实例反推。

## 已确认的完整交互设计

### 页面布局

- 顶部：本体地图／业务关系图切换，以及当前视图对应的规则版本或战略选择。
- 中间：分层地图或当前范围的业务关系图，提供缩放、适应视图、返回上一级与搜索定位。
- 右侧：选中对象类型的业务说明卡，或具体对象的现有业务详情。
- 保留列表阅读入口，窄屏以列表和详情为主，图形不成为获取信息的唯一方式。

### 图上的含义

- 本体地图节点表示对象类型，连线用业务语言说明关系；区域分组不解释为强制执行顺序。
- 业务关系图节点显示名称、类型、版本与正式／候选标记；责任人与经营状态仅在有授权依据时显示。
- 经营状态颜色与内容是否正式分别表达；未记录状态不推断为 Green，也不自动生成 Unknown 状态对象。
- 实例连线仅来自已记录、当前可读的精确引用；标注关系含义，点击可查看引用依据。
- Battlefield、Capability 与 Outcome 以所属对象中的定义项展开，不伪装成独立生命周期对象。
- 尚无实例的类型继续出现在本体地图。业务关系图的空结果仅说明当前身份和筛选下未读到记录；不可用接口、读取失败和空结果分别表达，不展示未授权数量。
- 概念说明中的动作是规则说明，不是执行按钮。PeriodReview 等分析产物按其自身可用性解释，不能统称为已审批；业务关系图不因其没有审批动作而排除必要分析依据。

### 视图联动

1. 本体地图 → 类型说明 → 查看实际数据 → 可见记录列表 → 具体对象关系图。
2. 具体对象 → 查看该类对象规则 → 切换到对象绑定的业务规则版本，并定位类型。
3. 返回时保留原战略、筛选、所选对象与视图位置；身份变化后重新验证并清理失效内容。

## 验收场景草案

- 无 Architecture 实例时，仍能在本体地图了解其定义项、关系和正式确认边界。
- 从 Mission 类型找到一条可见 Mission，看到其实际 PCO、LTCO、战略和存在的责任结构依据；未记录关系不补造。
- 正式 Mission 依据旧战略时，真实旧版关联默认可见；打开候选比较不会替换正式依据。
- 0.1 对象查看规则时显示 0.1，不把 0.3 的 Agent 立项权限套在旧对象上。
- 撤权、跨域、加载失败和分页未加载完不会被表达成完整关系图或业务零值。
- 阅读、筛选与展开均不产生业务变更，既有列表与详情仍可使用。

沿用既有只读及当前授权边界，继续使用 shadcn/ui 组件；本轮尚未选择图形布局工具。
