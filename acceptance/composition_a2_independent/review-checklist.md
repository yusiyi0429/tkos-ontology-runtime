# A2 实现审查锚点

这里记录独立审查关注点，不代表实现或验收结果。

- 新创建/目标动作/依赖/证据/读取都按真实对象的 ProtocolBinding 分派；支持登记不能突破编译白名单，A1 缺省登记不能被静默变成可写。
- Round 的成员定义、最新正式 Submission 集合和对象 CAS 分开。签认只推进 CAS，不改变 manifest 内容。公司 Reference 与所有正式 binding 的精确版本和有效期应有明确规则。
- 容量需从完整 Submission 汇总；两个域各自不过限也可能合计超限。available/reserved、资源/周期/单位、观察时点和 TTL 不得从客户端未核验声明得出。
- 新来源版本通过真实授权入口发布，即使业务数值相同也不能复用旧签认。信息性注释或未采用文档不纳入正式依赖闭包。
- 已发布组合材料应足以让参与者判断；只给不可读引用不算可签认。共享投影不能连带授予另一域原始证据、路径、数量或名称的访问权。
- 完整公司动作需要 CEO 对所有受控域有权；每个 DRI 只凭本人的指定任职签认。不要把跨域读取例外扩展成任意对象/证据读取权。
- 自然到期不受锁或 auth_epoch 阻止；最终屏障后检查全部必要任职和当前 DB 时钟，源有效性也不能在慢调用后沿用过期缓存。
- 所有冲突入口遵守同一 scope fence。并发证据记录真实 PostgreSQL blocking PIDs，不用线程启动顺序替代。
- 激活只产生公司组合基线、域承诺和 Mission 生效引用；ExecutionAuthority、IC 接收、WorkItem 与外部派发不得凭空出现。
- 一次激活中途故障后，所有 scoped 表、成功回执、事件及 outbox 必须恢复 SQL 快照。允许拒绝审计变化须显式列明。
- 新表 FORCE RLS、scope FK、不可变历史、mutable 状态写围栏及最小 app grants 均核查；旧实例语义、旧交付链和旧请求 hash 必须保留。
