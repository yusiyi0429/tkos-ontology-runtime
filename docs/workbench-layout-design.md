# 工作台布局重构设计记录（workbench UI v0.2）

针对「四页信息架构乱」的整改。设计方向由 Codex 给出，本文记录实施后的结构。
色板沿用蓝灰身份并收敛为：paper `#f4f6fa`、surface `#ffffff`、ink `#1e2c43`、
muted `#64748b`、blue `#315bb5`、line `#dce4ef`；绿/琥珀/红语义不变。无新字体、
图标或框架依赖；中文标题 PingFang SC 600，正文系统无衬线 14px，技术字段沿用 mono 11–12px。

## 外壳与导航连续性

```
┌──────────────────────────────────────────────────────────────┐
│ T TKOS 本体与记忆工作台        演练身份[CEO▾] [本地合成演练]      │
├──────────────────────────────────────────────────────────────┤
│ 当前对象  交付工作项… [WorkItem] rev 1206a8a1…   实例详情 动作与回执 │ ← 上下文条（有对象时）
├────────┬─────────────────────────────────────────────────────┤
│ 对象与关系 │                                                   │
│ 实例详情  │                  页面主区                            │
│ 动作与回执 │                                                   │
│ 记忆快照  │                                                   │
│ Context Pack│                                                 │
└────────┴─────────────────────────────────────────────────────┘
```

- 设计辨识点：顶栏下的「当前对象 + 版本」上下文条（`#tk-contextbar`）。页面围绕同一
  对象连续查看；从实例去回执、再回实例，始终是同一对象与用户选过的精确 revision。
- 导航状态是新增纯模块 `workbench/lib/focus.js`（仅内存，不写 localStorage）：
  `openObject`（换对象即清旧标题/revision）、`recordRead`（仅授权读取成功后回填
  标题/类型，异对象迟到响应被拒）、`selectRevision`、`navRoute`（主导航携带当前
  对象与 revision）、`clearFocus`（切身份立即清空）、`rememberCatalog`（目录类型/域
  的小范围内存记忆）。`renderRoute` 从 hash 同步 objectId，页面读取成功后经
  `ctx.reportObject` 回填标题 —— 任何 401/403/404 都不会残留先前身份的数据。
- 主导航去掉装饰性 01/02 编号（导航不是步骤）；Context Pack 加中文名「记忆快照」。
- 首次无当前对象时实例/回执页仍 fallback 演练 WI 锚点；从 catalog 打开对象即替换
  当前对象。hash 深链接语义不变（`#/instance/{id}?rev=`、`#/receipts/{id}?r=` 等）。
- 英文大 eyebrow（OBJECT INSTANCE 等）全部移除；页头只剩面包屑 + H1 + 一句中文副标题。
  演练身份与「本地合成演练」标识保留在顶栏唯一明显位置；API 验证入口降级为侧栏小链接。

## 页 01 对象与关系

```
H1 对象与关系 + 一句说明
┌────────────┬───────────────────────────────────────────┐
│ 对象目录     │ [业务域▾] 过滤条（首屏）                     │
│ 10 类型列表  │ 实例列表 · 当前类型（分页实例列表，首屏可见） │
│ 中文名为主   │ ▸ 类型定义与字段（默认收起：typed refs/schema） │
│ 英文小字mono │                                           │
└────────────┴───────────────────────────────────────────┘
```

类型定义/schema/typed 字段从主列中部移到实例列表之后的 `<details>`；目录事实、
分页、空态、error 全部保留。类型/域选择在同次会话内小范围保留（内存）。

## 页 02 实例详情

```
H1 对象标题   [类型 · lifecycle]            [动作与回执 →]
[概览] [版本与内容] [来源关系]   ← 本页页签（aria-pressed，切页签不发请求）
（仅 WI 锚点概览）三状态带：交付 / Outcome / MF（当前状态）
```

- 三状态带只在所选对象 == 演练 WI 锚点且处于概览页签时显示；Outcome 只读 `outcome_achievement`，
  缺失即「未提供」，绝不用 confirmed 推断。非锚点对象不再拉取锚点三请求。
- 概览（WI 默认）：交付轨迹 → 提交 v1/v2 + 评审 + 证据（主列）/ 责任人摘要（右列）。
  完整 ID/hash/assignment/baseline 收进「溯源信息」details；版本指针折叠为
  「版本指针」details。v1/v2 仍是提交序号，不是 object_version。
- 版本与内容（非 WI 默认；显式 `?rev` 深链接默认落此页）：revision 选择器 +
  latest/effective 标记 + payload 内容在前；证据对象的「读取原始证据」按钮保持可见；
  revision 完整 ID/hash/有效区间收进 details。
- 非 WI 概览只给对象基本信息与「查看对象内容」入口，不显示无关演练三状态。
- details 展开状态经 `openDetails` 集合 + capture 阶段 toggle 监听在异步重绘间保持；
  证据字节加载不会收起已展开区块（`textContent` 注入不变）。

## 页 03 动作与回执

```
H1 动作与回执 · 当前对象：标题                 [← 返回实例]
┌──────────────┬────────────────────────────────────┐
│ 动作历史列表    │ 回执详情：动作 + 评审结果tag + 时间      │
│ （分页加载更多） │ 提交序号 v{n} / 状态                  │
│              │ ▸ 审计字段（receiptID/actorID/auth_epoch │
│              │   /result 原文/对象版本）               │
└──────────────┴────────────────────────────────────┘
```

- 修复了列表 panel 嵌套 panel 的问题；底部大段「审计展示约定」面板收敛为一行小字。
- 退回补充标注为业务评审结果（非权限拒绝），用一行短提示而非独占卡片。
- 无回执时详情区给清晰空态（`receiptDetailState`），不再无限 loading；
  列表加载完成未选中时提示「从左侧选择」。目标对象链接保留。

## 页 04 记忆快照（Context Pack）

```
H1 记忆快照（Context Pack）
┌─ 输入栏 380px ──────┬─ 结果栏（常驻）──────────────────┐
│ [新建快照|回读快照]    │ 快照 · 纳入 n · 排除 m            │
│ 新建：选对象→双时间→生成 │ 来源 / 记录时间 / 双时间 / 条件提示     │
│ ▸ 手动 UUID（默认折叠） │ ▸ 技术溯源（快照 ID/hash）  │
│ 回读：快照 ID + 回读    │ 选中对象（评审投影在前，ID 收 details）│
└────────────────────┴───────────────────────────────┘
```

- 两个模式同一时间不混排；切模式/改条件不发任何请求（POST 仍只有「生成审计快照」
  按钮，busy 防重复不变）。时间字段中文名为主、技术参数名小字 mono 保留。
- 结果栏先显示来源与纳入/排除数量，完整 ID/hash 进「技术溯源」；多份快照通过选择器切换，
  同时只呈现一份结果，保留各自时间条件。窄屏自然单列。
- 切角色旧快照清空、GET 回读重新授权（沿用路由级重新渲染与缓存清空）。

## 独立审查后的收尾修正

Codex 补齐同对象旧响应的导航/身份保护、读取前清除旧标题、无 rev 重新打开时回到当前版本、
目录深链接筛选返回、回执列表错误空态。Context 结果常显双时间，回读模式不再与隐藏表单比较；
选择对象保留名称，手动 UUID 草稿跨模式保留。多份快照只显示当前选择，切换不发写请求。
移动目录采用横向类型选择，实例信息上下排列，避免长名称被压成窄列。
