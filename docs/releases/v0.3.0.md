# v0.3.0：Anchor 与本体可视化

本版汇总 v0.2.1 以来已合并的 Runtime 功能。发布版本号与 Method 契约版本分别管理，不自动升级历史对象的协议绑定。

## 新增能力

- Clark 工作面支撑：当前身份、月度核对、周进展及会议场景记录，保留正式业务动作的授权与效力边界。
- Method 0.2 生命周期：研究、会议资料、判断与战略更新的合法动作及来源。
- Method 0.3 Anchor：整体版本化 Architecture、Operating State、Problem、CEO Agent 立项与原子移交。历史目标保留原依据，正式战略确认仍由本人完成。
- 只读经营看板：本体地图、0.1/0.2/0.3 业务规则说明、授权实例目录、精确版本关系图，支持历史依据、候选区分及移动端阅读。默认关闭，不产生业务写入。

## 交付形式

Release 附件包含 `tkos_memory_service-0.3.0-py3-none-any.whl`、`tkos_memory_service-0.3.0.tar.gz`、amd64/arm64 两套完整离线包、`SHA256SUMS`、发布清单与脱敏验收报告。前端生产资源随 Python 包交付。GitHub 同时提供标签对应的仓库源码归档。

离线附件已补齐：

- `tkos-ontology-runtime-v0.3.0-linux-amd64.tar.gz`
- `tkos-ontology-runtime-v0.3.0-linux-arm64.tar.gz`
- `release-manifest-amd64.json`、`release-manifest-arm64.json`
- `README-v0.3.0.md`、`offline-acceptance.json`、`build-offline-v0.3.0.py`

每套恰含 Runtime API、Worker、PostgreSQL/pgvector、MinIO Server、MinIO Client 五类镜像。业务源码仍固定到原 v0.3.0 标签 `b4391fa`；部署模板修复来自 `d168ee3`，另行记录在 manifest 的 `deployment_source_ref`，没有重写标签。

本次修复旧模板未设置默认证据保留期的问题。证据桶默认采用 30 天 GOVERNANCE 保留期，可通过 `MINIO_RETENTION_DAYS` 按组织要求调整。完整结果见[离线验收](v0.3.0-offline-acceptance.md)。两架构均已通过实际加载、原始 Compose 启动、迁移/权限、证据存储、58 项业务/看板与 46 项本体检查；amd64 是 Apple Silicon 上的 Docker 仿真运行，不代表独立 amd64 物理机性能验收。

所有临时验收容器和数据卷已清理，现有 Runtime 与 Clark 运行容器未更新。

## 验证依据

发布检查包括版本一致性、锁文件、前端资源清单、Python dashboard 101 项回归、wheel/sdist 构建及逐文件资源验证。紧邻发布的功能验收包括前端 94 项、新增本体 HTTP/SQL 46 项、Method 0.3 看板场景 58 项、0.1 数据副本 53 项，以及真实浏览器和只读数据库核对。

完整证据与截图见 [本体视图验收](../runtime-ontology-views-acceptance.md)。Anchor 35/35、Method 0.2 22/22 等此前功能验收见 [Anchor 验收](../runtime-anchors-v03-acceptance.md)，属于功能开发阶段证据，不计作本次重新执行。

## 升级及边界

数据库迁移是追加式，当前迁移至 0025；使用新源码执行迁移前应备份并在隔离环境验证。发布不自动迁移生产库，不升级旧 0.1/0.2 对象，不创建正式身份或授权。

Clark 页面/BFF 由伙伴维护。本 Release 不代表 Clark 接线、业务真实模型收拢、生产 SSO、远程部署或 M2 执行链验收通过。源码预览中的合成数据不随包发布。
