# tkos.world/0.1 静态截面实验·第二轮：按建议调整后的三组对照

票 #32 批次 D。第一轮（#29）的报告见 [world-v01-experiment-report.md](world-v01-experiment-report.md)。

这一轮先把第一轮的建议 1–4 落到代码：

1. MCP 取上下文只交给模型包 id、Markdown、覆盖与预算摘要；
2. Why 路径沿单元长期目标的 `goal_ref` 多取一跳，带上公司级长期目标的定义类块；
3. Markdown 开头按问题给出处（六问指引）；
4. 事件行写出记录人与被指派者的名字；工具说明写明 `question` 只做记录、同一问题取一次即可。

再按建议 6，同一模型、同一数据、同一口径跑三组：

- **B**：固定路径的取上下文，每问一次；
- **A**：模型遍历，四个读工具都有，含取上下文；
- **A0**：模型遍历，不给取上下文。

数据摘要见 [world-v01-static-cross-section-round2.json](experiments/world-v01-static-cross-section-round2.json)。本实验不作为验收门。

四点结论：

- **瘦身生效。** A 每次运行拿到的字符数降到第一轮的四分之一，低于全量塞入的一半。B 经 MCP 的返回从 5.6 万字符降到 1.3 万。
- **「A 不高于 B」这一条仍不达标，而且这样定义不可能达标。**
  - A 用的就是 B 的包，再多读任何东西都会超过 B，第一轮报告已指出这一点。
  - 这一条要么改为「A 不超过 B 加一个固定余量」，要么只用来比较 A0 与 B。改口径要先定，本轮没有改。
- **召回：A 与 B 都到了 1.00。**
  - 第一轮每次都漏的公司级长期目标「目标成果」块，这次经 `goal_ref` 一跳取到了。
  - 纯遍历的 A0 只有 0.52：平均每次只读到约 2 个对象，Mission 以上的链和九月的事件大多没走到。取上下文对召回仍是决定性的。
- **按问题组织有帮助，但 Why 还弱。**
  - 回答引用的覆盖从 0.49 升到 0.60，发生了什么从 5/12 升到 8/12，现状从 5/9 升到 6/9。
  - Why 只从 0/12 升到 3/12：包里已经有整条链和指引，回答仍多半只拿 Task 与会议解释「为什么」。
  - Who 仍是 6/12。

## 实测、推断与未验证

**实测**

- 上面的指标都由 `experiments/world_v01/metrics.py` 从 MCP 运行日志与结构化回答机械算出。
- 回答引用的覆盖、调用模式是写报告时另算的，口径与第一轮相同：期望引用若是整个对象，回答引了它的某个版本或块也算。
- 三组都没有取到任何诱饵，回答里八类反例都是 0 次。

**推断**

- **A0 召回低的原因**：它在起点附近读两三个对象就作答，没有沿 Mission、周期目标、长期目标往上走，也没有翻九月的事件。这是从每次读到的对象数与漏掉的引用推断的，没有逐次看模型的推理。
- **零反例对 A0 的意义**：A0 离开了起点，零反例比第一轮更有意义。但它读得浅，诱饵大多仍在它没走到的地方，所以还不能说明「走到了也不会用」。
- **Why 的覆盖仍低**：按问题组织让模型更常引用上层对象，但它仍倾向用最近的 Task 与会议解释「为什么」。这是措辞与取舍的问题，不是包里没有。

**未验证**

- **回答内容是否正确**：五项指标只看引用。关键回答的人工核验材料已经准备好，等 E&O DRI 核验，结果另行补记。
- **其他模型与推理档**：只跑了一个模型、一个推理档。
- **「A 不高于 B」该怎样改**：没有定。
