- **固定上下文作答（F）最好，也最省。**

  - 交给模型的字符只有 A 的 47%，召回、可追溯、反例都达标。
  - 给模型工具（A）没有带来更好的回答：A 拿的是同一个包，18 次里有 12 次还读了起点以外的对象，覆盖反而是 0.57。原因没有验证，见「推断」。
- **纯遍历（A0）仍然不够。**
  - 召回 0.56、确定性 0.89，两项都不达标，覆盖 0.43。Mission 以上的链和九月的事件大多没走到。
  - A0 在 Why 问里读到 3 次旧版本对象（诱饵），回答一次都没有引用。
- **「A 不高于 B」这一条，按现在的定义谁都过不了，而且两边口径不一。**
  - B 按渲染后的 Markdown 计，作答组按交给模型的 JSON 计。F 拿到的正是 B 的包：按同一口径比恰好 1.00，按规格口径却是 1.37。
  - 建议改成同一口径（都按交给模型的字符），再定一个余量，或者只保留「不超过全量塞入的一半」。改口径要你定，本轮没有改。
- **Why 在各组都弱。** 覆盖分别是 F 4/12、A 3/12、A0 0/12。包里已经有整条目标链和六问指引，回答仍多半只拿 Task 与会议解释「为什么」。
- **B 的 Markdown 从第一轮的 7,390 字符增到 9,760**，多出的 2,370 全部来自这轮加的三项：

## 口径

- **字符**：
  - A、A0 是一次运行里工具返回给模型的 JSON 字符数；
  - F 是放进提示词的取上下文返回，与 B 经 MCP 的 JSON 相同；
  - B 另记渲染后的 Markdown，这是规格的预算口径。
  - 各组取三次的平均，再对六问平均。
- **确定性**：同一问三次运行取到的集合两两 Jaccard 的平均。F 的包是固定的，这一项必然是 1.00；比较回答的稳定性要看所引集合一致率。
- **回答引用的覆盖**：标准答案应引用的里被回答引到的比例；期望引用是整个对象时，引了它的某个版本或块也算。与第一轮同一口径，现在由 `metrics.py` 计算、写进 JSON。
- **调用模式**：同样写进 JSON，口径见 `metrics.py` 的说明。

## 实测、推断与未验证

**实测**

- 上面的指标、覆盖与调用模式都由 `experiments/world_v01/metrics.py` 从 MCP 运行日志与结构化回答机械算出，写在数据摘要里。
- 各组都没有引用任何诱饵，回答里八类反例都是 0 次。A0 读到的 3 次诱饵都是 Why 问里的旧版本对象。
- B 的 Markdown 增量拆解，是从这次实验库里 B 组的包逐段量出来的。三项之和正好等于增量。

**推断**

- **F 胜过 A 的原因**：A 与 F 拿到同一个包，A 还多读了东西，覆盖却更低。可能是多读的内容分散了回答，也可能是遍历时模型更倾向引用自己读到的近处对象。两种解释都没有验证，没有逐次看模型的推理。
- **A0 召回低的原因**：它在起点附近读两三个对象就作答，没有沿 Mission、周期目标、长期目标往上走，也没有翻九月的事件。这是从每次读到的对象数与漏掉的引用推断的。
- **诱饵**：A0 读到旧版本却没引用，这是「走到了也不会用」的第一批实例。但只有 3 次、都是同一类，还不足以下结论。

**未验证**

- **回答内容是否正确**：五项指标只看引用。关键回答的人工核验见下一节，等 E&O DRI 核验，结果另行补记。
- **其他模型与推理档**：只跑了一个模型、一个推理档。
- **「A 不高于 B」该怎样改**：没有定。

## 已知问题：六问指引与覆盖口径不同

包里的「六问覆盖」（`cover()`）是 0.1 契约的判定，随冻结不改。「六问指引」（`guide()`）是这一轮加的阅读出处。两者对为什么、做什么、谁负责、凭什么四问的取法不同，同一个包里可能指引给了出处，覆盖却报缺口。

统一口径留给下一个 world 版本，见 `world_v01_context.py` 与 [ADR-0007 的补记](adr/0007-context-pack-trail-retention.md)。
