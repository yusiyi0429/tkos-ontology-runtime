# v0.5.0：tkos.world/0.1、Method 0.5 与评估整改

本版汇总 v0.4.0 以来已合并的 Runtime 功能。发布版本号与协议契约版本分别管理，不自动升级历史对象的协议绑定。从本版起，tag、Python 包版本、离线包文件名、镜像标签与发布文档统一用同一个版本号（`v0.5.0`／`0.5.0`），镜像标签形如 `<仓库>:v0.5.0-<架构>`。

## 新增能力

- **`tkos.world/0.1` 业务世界模型**：与 `tkos.method` 并存的独立协议，按 CEO《企业业务世界建模框架》把公司表达为九类一级对象（公司、战略、责任单元、长期目标、周期目标、Mission、Task、Activity、状态快照）、内容块、少量关系，以及所有对象共有的状态快照与事件。13 个动作经 prepare 与 commit 提交；承诺与确认走门；生命周期由事件推导。读投影四条（对象、状态、事件、子对象）加取上下文：沿主干组装分层上下文包，同时给出检索计划、覆盖与预算裁剪记录，并落表留存。契约见 [tkos-world-0.1.md](../contracts/tkos-world-0.1.md)。
- **`tkos-world-mcp`**：给 Agent 的 stdio MCP server，是 HTTP 读写面的薄壳（四读三写），在可选依赖组 `mcp` 里，基础安装不带。配置见 [Codex 接入说明](../world-mcp-codex.md)。
- **`tkos.method/0.5`（本体 v0.7 对齐）**：Constraint 一级对象与按范围确认、LTCO 审视结论、CEO 确认复盘并由下期 PCO 承接、Mission 的贡献／依赖／资源与责任域 DRI 唯一承诺、生成即正式的带起止时间状态，以及公司集合视图与确认记录投影。契约见 [tkos-method-0.5.md](../contracts/tkos-method-0.5.md)。
- **凭证生命周期**：签发必须写明有效期（或显式不设），支持轮换（带宽限期）与吊销；立即吊销先推进 `auth_epoch`，与在途事务串行（迁移 0038）。

## 加固与整改（两份外部评估，追踪票 #32）

- 迁移 0037 收回只读角色在三张只增表上的写权；迁移器加校验和、互斥锁与编号约束。
- 治理事务加 `lock_timeout` 与 `statement_timeout`；请求体上限（413）；请求 ID 与等锁／持有时长记录。
- 证据：原始字节移出 scope 栅栏，改为两段事务；对象键按内容寻址；上传可带幂等键；另加孤儿对象对账。
- `payload_hash` 与请求摘要统一走 `canon`（历史哈希不变，非法输入从 500 改为 422）；健康检查不再回显数据库错误原文。
- 外部效果派发带 Bearer 认证，参考接收端支持多令牌轮换。
- 删除从未被读取的 artifact 桶：应用 S3 身份不再持有 `s3:DeleteObject`。**已部署环境**的 `minio-init` 只在策略不存在时创建，需手工重建策略才能收回该权限。
- 发布授权规则成为唯一来源：验收建库、隔离栈与远程生产都按 `deploy/offline-release/db_admin.py` 授权。
- provider HTTP 共用（不读代理、不跟随重定向、响应上限、https）、S3 与数据库连接配置统一、`DB_CONNECT_TIMEOUT` 全路径生效。
- 删除零引用的旧 Memory 核心模块与会连到 Clark 联动库的旧建库脚本；CI 覆盖无库测试、应用角色与迁移所有者两轮数据库测试、看板与构建。
- 离线部署：MinIO 应用密钥文件须为属主 10001、属组 0、权限 440（原先 README 写的 600 在 Linux 上会让 `minio-init` 读不到而启动失败）。

## 交付形式

Release 附件包含 `tkos_memory_service-0.5.0-py3-none-any.whl`、`tkos_memory_service-0.5.0.tar.gz`、amd64／arm64 两套完整离线包（`tkos-ontology-runtime-v0.5.0-linux-<架构>.tar.gz`）、`SHA256SUMS`、两份架构 manifest 与顶层 `release-manifest.json`。每套离线包恰含 Runtime API、Worker、PostgreSQL 17＋pgvector、MinIO Server、MinIO Client 五类镜像（标签 `<仓库>:v0.5.0-<架构>`），以及该版本的完整源码归档；Clark、Nginx、模型服务、凭据、数据库备份与业务数据不在包内。镜像内 `/opt/tkos/docs/` 带齐 Method 0.4、0.5 与 world 0.1 的控制面安装材料。前端生产资源随 Python 包交付。GitHub 同时提供标签对应的仓库源码归档。

离线包与 wheel／sdist 由 `72897d2` 构建，与本标签只差两份发布文档与 README；全部构建输入（Dockerfile、pyproject.toml、uv.lock、src、deploy/offline-release）一致，可从本标签复现。

## 升级及边界

数据库迁移是追加式，当前迁移至 **0038**（新增 `0029_method_v05.sql` 至 `0038_credential_lifecycle.sql` 共 10 个）。使用新源码执行迁移前应备份并在隔离环境验证。发布不自动迁移生产库，不升级旧 0.1–0.4 对象，不创建正式身份或授权；world 0.1 与 Method 0.5 需经控制面按 scope 安装后才可用。

从 v0.4.0 升级时：`minio-init` 只在应用策略不存在时创建它，所以已部署环境应用策略里的 `s3:DeleteObject` 不会被自动收回，需手工重建该策略；原 `artifact` 桶也不会被自动删除。MinIO 应用密钥文件的属主与权限按[离线部署说明](../../deploy/offline-release/README.md)设为 10001:0、440。

`tkos.world/0.1` 已部署到一个给 Agent 侧联调的独立实例（[deploy/world-lab/](../../deploy/world-lab/README.md)），不计作生产部署。

**尚未验证**：Clark 接线与浏览器端到端、真实业务模型、生产 SSO 与正式身份（[ADR-0008](../adr/0008-enterprise-identity-and-formal-profile-path.md) 待组织裁决）、生产部署与切换、登录后的工作台浏览器复核、world 0.1 第二轮实验关键回答的人工核验。
