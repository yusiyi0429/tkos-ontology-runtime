# v0.6.0：tkos.world/0.2 锁版与 Content Pact

本版汇总 v0.5.0 以来已合并的 Runtime 功能。发布版本号与协议契约版本分别管理，不自动升级历史对象的协议绑定。tag、Python 包版本、离线包文件名、镜像标签与发布文档统一用 `v0.6.0`／`0.6.0`，镜像标签形如 `<仓库>:v0.6.0-<架构>`。

## 新增能力

- **`tkos.world/0.2` 业务世界模型（2026-09-30 锁版，#86／#88）**：与冻结的 `tkos.world/0.1`、`tkos.method` 并存的新契约版本，不迁移 0.1 数据、不建桥，只在新建的 scope 启用。
  - 三层：业务对象（Company、Strategy、ResponsibilityUnit、LongTermGoal、PeriodGoal、Mission、Task、Activity，Activity 转为正式类型）、身份投影（责任主体、角色指派、代记委托）、时间记录（状态快照、事件、上下文包）。
  - 语义组件与 `对象@版本#块/组件` 引用；Event—生命周期—State；Issue 作为问题组件（提出、路由、退回形成、处置）；委托与代记；取上下文按六问组织。
  - 块、组件类型与各类对象的状态项按方法侧 **Content Pact 首版**替换，逐项对照见[映射表](../world-v02-content-pact-mapping.md)。
  - 唯一迁移 `0039_world_v02.sql` 自此冻结，回到 append-only。契约、登记、profile 与支持登记的钉定哈希见[锁版检查点](../world-v02-freeze-checkpoint.md)；契约见 [tkos-world-0.2.md](../contracts/tkos-world-0.2.md)，待决项的落稿在契约第 19 节。
- **`tkos-world-mcp` 支持 0.2**：`TKOS_WORLD_CONTRACT_VERSION=tkos.world/0.2` 时暴露 0.2 的 Agent 面（五读八写）；不设时仍是 0.1。见 [Codex 接入说明](../world-mcp-codex.md)。
- **`tkos-world` 命令行（#44／#45）**：给人和脚本用的 HTTP 面薄封装，在基础安装里；只做 Agent 面，0.1 的 `act` 只接受记外部事件、写状态快照、修订无门对象三个写动作，同样可选 0.2。见 [CLI 说明](../world-cli.md)。
- 镜像内 `/opt/tkos/docs/` 增加 world 0.2 的契约、登记、profile 与支持登记，控制面可只用镜像内材料为新 scope 安装 0.2（参考 `deploy/world-02/provision-and-install.sh`）。

## 交付形式

Release 附件包含 `tkos_memory_service-0.6.0-py3-none-any.whl`、`tkos_memory_service-0.6.0.tar.gz`、amd64／arm64 两套完整离线包（`tkos-ontology-runtime-v0.6.0-linux-<架构>.tar.gz`）、`SHA256SUMS`、两份架构 manifest 与顶层 `release-manifest.json`。每套离线包恰含 Runtime API、Worker、PostgreSQL 17＋pgvector、MinIO Server、MinIO Client 五类镜像（标签 `<仓库>:v0.6.0-<架构>`），以及该版本的完整源码归档；Clark、Nginx、模型服务、凭据、数据库备份与业务数据不在包内。镜像内 `/opt/tkos/docs/` 带齐 Method 0.4、0.5 与 world 0.1、0.2 的控制面安装材料。前端生产资源随 Python 包交付。GitHub 同时提供标签对应的仓库源码归档。

离线包与 wheel／sdist 由 `a38beae` 构建，与本标签只差两份发布文档与 README；全部构建输入（Dockerfile、pyproject.toml、uv.lock、src、deploy/offline-release）一致，可从本标签复现。第三方镜像 digest 与 `requirements.lock` 与 v0.5.0 相同。

## 升级及边界

数据库迁移是追加式，当前迁移至 **0039**（新增 `0039_world_v02.sql` 一个）。使用新源码执行迁移前应备份并在隔离环境验证。发布不自动迁移生产库，不升级旧对象的协议绑定，不创建正式身份或授权；world 0.2 需经控制面按 scope 安装后才可用，且只在新建的 scope 启用。已有 0.1 数据的 scope 保持 0.1，切到 0.2 另立一步。

从 v0.5.0 升级：换离线包的部署文件与镜像，沿用 env、MinIO 应用密钥与数据卷重跑 `start-offline.sh`，只会应用 0039。v0.4.0 起遗留的应用策略 `s3:DeleteObject` 与 `artifact` 桶仍需按 [v0.5.0 发布说明](v0.5.0.md)手工处理。

给 Agent 侧联调的 world-lab 实例仍跑 v0.5.0（world 0.1），本版不升级它；world-02 实验实例按其[部署说明](../../deploy/world-02/README.md)换版本即重建，不计作本次发布的一部分。

**尚未验证**：Clark 接线与浏览器端到端、真实业务模型、生产 SSO 与正式身份（[ADR-0008](../adr/0008-enterprise-identity-and-formal-profile-path.md) 待组织裁决）、生产部署与切换、登录后的工作台浏览器复核、world 0.2 在 world-lab 或 world-02 实例上的部署、0.2 实验 B 与四种取法的结论。
