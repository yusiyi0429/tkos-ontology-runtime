# A2 公司组合：本地独立验收报告

结论：**A2 公司组合已通过本地合成数据独立验收。** 最终一轮真实 HTTP／PostgreSQL 验证完成 18/18 类用例、66/66 项必验检查、27 个场景及 8 项补充门禁；旧交付回归和项目测试使用同一份最终源码。此结论仅覆盖 A2，不代表完整 TKOS Method、真实业务成功或生产发布。

验收分支 `codex/runtime-a2-company-composition`，基础提交 `2e385a20a47228fe451557614fe5efab5e8118eb`。开发已按用户要求切回 Kimi Code；额度中断期间曾使用 MiniMax。Codex 负责代码审查、独立 HTTP／SQL 验收及验收发现问题的修复。下文记录 2026-09-10 验收结束时的状态，当时尚未提交、推送、发布或部署；后续 Git 合并不代表服务已部署。

## 已验证的业务行为

- 支持公司参照和容量来源受控发布、开启组合轮次、两个参与域正式提交、形成完整公司组合、当前 CEO 与各域 DRI 对精确版本签认，以及整体生效。生效时原子产生选定 Mission 和 DomainCommitment；不会自动下达 A3 执行授权、生成 WorkItem 或完成 IC 交接。
- 成员增减、约束来源及正式提交版本变化会阻止旧组合生效。R1 容量 3 → R2 容量 2 → R3 容量 3 仍须重新签认；旧 manifest 即使携带最新 CAS 和当前代次也被拒绝，不能借“内容改回来”恢复旧签认效力。历史版本、签认和回执保留。
- 汇总全部需求与约束依赖，检查容量、冲突、循环及依赖规模。共享依赖按最长路径计深度：8 层可用，9 层在 prepare 和正式写入时均被拒绝，拒绝后业务数据不变。
- 候选形成前检查判断来源的精确版本、内容 hash、参与者共享权限与有效期。CEO 可读但参与者不可读的判断证据不能随组合发布。读取时重新检查当前角色、策略和引用权限，历史签认不构成永久读取授权。
- 撤权、签认人自然到期、来源自然到期、并发修改与重复提交均有真实数据库验证。两个 API 进程观察到实际锁等待与先后顺序；成员写入中途故障时，组合、成员、回执及任务变更整体回滚。
- 工作台读取保留未决冲突、判断与形成时审查结果，并准确标注 7 类 A2 对象的协议解释状态。`readiness.basis=at_form` 只表示形成时记录；当前生效仍须重新验证授权、版本、来源、签认与容量。本轮没有执行 A2 页面浏览器验收或 Clark 联调。

## 环境与剩余边界

业务验收仅使用本机独立库 `tkos_a1_a2_c037ad7ac0a54cdb`、合成主体与普通应用角色。应用角色不是数据库 owner、superuser 或 BYPASSRLS；全部 governed 表启用 FORCE RLS。业务发布、签认、组合与交付均通过真实 HTTP；SQL 用于受控初始化、迁移、只读判定及回滚的负向权限探针，不直接制造成功业务状态。

19 个暂缓部署文件及现有 27 个容器（14 个运行）的身份、镜像引用、状态和端口核对一致。现有工作台演示与 Clark 未升级，验收 API 和开发 CLI 进程已结束。

撤回签认、Profile 迁移、暂停、A3 执行授权、IC 责任交接、远程部署均未在本轮交付；未知动作被拒绝只证明入口围栏。后续工作台升级、Clark 联调和真实企业业务验证需要各自独立验收，不能由本报告推断完成。
