# M1A＋M1B 底座 API 独立验收矩阵

状态：**2026-09-11 本机独立 API 验收通过：18／18 组、98／98 条检查、8／8 个环境门槛**。最终运行使用 967 次真实 HTTP 请求，包含 60 个预期拒绝和 2 次受控事务故障。摘要及源码清单见 [method-summary.json](acceptance/method-summary.json) 和 [method-summary-source-sha256.json](acceptance/method-summary-source-sha256.json)。不得以测试脚本存在、建表、OpenAPI 或受控 Agent 文本替代实际 API 结果。

基线为 M1A L4 revision 21、M1B L5 revision 837 和本轮用户批准的完整底座计划。新协议为 `tkos.method/0.1`；历史兼容基点为 `1b8cec9cc30e561e3570bc5dd010a09126f283c2`。机器可执行的检查清单位于 `acceptance/method_independent/matrix.py`，所有必需检查及环境门槛全部完成后，报告才允许给出 `method_api_accepted: true`。未执行、缺失、场景中途异常均不计通过。

| 编号 | 业务范围 | 必须观察的结果 |
|---|---|---|
| METHOD-01 | 信号和战略议题 | 多来源证据、Potential Issue 修订历史、CEO 确认 Strategic Issue、明确指定研究 DRI。其他人或 Agent 不能冒充 CEO。 |
| METHOD-02 | 研究澄清 | Memo 精确版本和来源、个人 Agent 澄清、双 Agent 校验、二次澄清和人直接解决、指定 DRI 发布计划。 |
| METHOD-03 | 报告及预审 | CEO Agent 可预审；退回后修改报告再提交；旧预审不能放行新报告，未获当前版本合格预审不能开会。 |
| METHOD-04 | 会议及 Agreement | 原始会议材料、双纪要、差异记录、DRI 确认最终纪要；目标未达成再开一轮会议；CEO 另外确认 Agreement。三类判断不能互相代替。 |
| METHOD-05 | 正式战略更新 | CEO 决定调整，CEO Agent 针对确切当前版本提出方案，Co-agent 审查，CEO 正式确认；Strategy 与 map 一起生效，保留 Agreement、方案及回执来源链。 |
| METHOD-06 | 不变更与域内判断 | 不需调整时以原因完成当前轮次并保留战略，不自动关闭议题或创建执行任务。域内调整只写 StrategicJudgment，支持同对象再次更新且保留旧版本，不改经营承诺；判断来源授权不能扩大为全域资料授权。 |
| METHOD-07 | 原子事实和复盘 | BusinessFact 必需字段、原始来源及保留旧记录的纠正；同人公司 CEO 与域内 DRI 并存时按操作域选择责任，另一域只有 IC 不能借用公司 CEO 写事实。PeriodReview 绑定确切事实与目标版本，可重新生成；无需审批即可作为分析输入，不能因此改变目标或授予执行权。 |
| METHOD-08 | LTCO 审视 | 建议、CEO 退回反馈、修订后确认确切 LTCO；以已生效战略为依据，不把事实复制进目标正文。 |
| METHOD-09 | 共同核对 | 固定 PCO＋Mission 版本集和参与者；本人评论、撤回、替代，保留历史且只有一份有效意见；Agent 辅助不冒充本人。 |
| METHOD-10 | 收拢和整组确认 | 关窗封存有效意见，迟到评论拒绝；每窗一次正式收拢，记录取舍及候选；CEO 附原因重开且用候选为基线；整组原子确认，无旧 A2 全员签认门槛。 |
| METHOD-11 | Mission 关系 | 单 Owner 支撑两个成果、Owner 与目标 DRI 同人成功；错误 PCO 版本、不存在的成果或 Owner 重复参加均拒绝；关系不反向复制进目标正文。 |
| METHOD-12 | 跨方法版本 | M1B 引用 M1A 生效版本；草稿不能取代依据；新战略产生影响提示，已确认旧目标继续有效；未确认的失效依据不能暗中通过，新周期使用新战略。 |
| METHOD-13 | 记忆和 Context Pack | 区分原始材料、分析、人的决定、复盘；按角色、阶段、用途提供确切采用版本和排除原因，历史名称及责任按引用版本解析；评论不增加业务正文版本。 |
| METHOD-14 | 权限 | Agent 冒充本人、非指定责任人、无关域读取均拒绝；窗口只授予固定目标和评论读取，不泄漏源资料；撤权后已准备写入及回执重试不能恢复授权。 |
| METHOD-15 | 并发与幂等 | 关窗／评论竞争有串行化结果；并发确认仅一个赢家；相同请求返回原回执，同 key 改请求冲突，旧版本必须重新读取。 |
| METHOD-16 | 事务与恢复 | 战略和候选首笔写入后注入失败，整个事务回滚；孤立存储材料不算成功；重启后对象、来源、回执、运行步骤和尝试可查，重放无重复效果；暂停／恢复可追踪。 |
| METHOD-17 | 协议与下游边界 | 服务器按对象绑定协议，客户端不能降级；旧通用入口不能绕过治理，prepare／execute 一致；新版 Mission 提供明确承接投影，无 M2 责任约定不能自动授权。 |
| METHOD-18 | 历史兼容 | 旧序列化、现有 A1 模型／HTTP 协议／序列化测试、A2／A3 完整独立矩阵及 legacy 交付回归；升级前对象、回执和效力不变，新协议不重释 Contract-A；历史读取仍按当前权限复核。原 A1 的完整控制维护及部署场景未重跑。 |

验收使用新建 `tkos_a1_method_*` 数据库，先从已接受 A3 源码迁移到 0020，再升级本轮迁移。既有数据库、容器、Clark 和 19 个暂缓部署文件保留。身份／角色／政策允许用隔离控制夹具建立；任何业务对象、确认、窗口评论、复盘、回执必须通过真实 HTTP 创建。应用进程只持普通应用数据库角色，原始证据经过实际本机对象存储。

独立门槛还包括：源文件在一次验收中不变、基线来源可核对、迁移重放无新增迁移、普通应用权限、不可变历史、真实证据存储、无外部业务派发、原有环境保留。失败注入只能暂停或抛错，不允许替换授权或预先写入成功结论。
