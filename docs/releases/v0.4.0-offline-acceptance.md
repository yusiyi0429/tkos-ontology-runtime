## 与 v0.3.0 离线验收的差异（重要）

v0.3.0 在容器内另跑了**业务/看板链 58 项**与**本体 HTTP/SQL 检查 46 项**。**本轮没有重跑这两套矩阵**：它们由 `acceptance/dashboard_0_3` 与 `acceptance/ontology_views` 提供，固定在 Method 0.3／迁移 0025 的基线上，且其建库助手把宿主 PostgreSQL 容器写死为早期部署的项目名，直接对 v0.4.0 容器复用会得到与被测版本不符的结论。

本轮改为在发布容器内执行一条**真实治理动作链**（授权上传 → 版本化对象存储写入 → 原始字节回读 → 越权围栏 → 回执落库与读取 → 对象保留期），覆盖的正是 v0.3.0 当时暴露问题的那条路径。这条链比 58＋46 项窄，**不能等价替代**；把 0.3 矩阵迁移到 0.4 基线是单独一件事。

## 发布物与来源

每个离线包恰含 Runtime API、Worker、PostgreSQL 17＋pgvector、MinIO Server、MinIO Client 五类镜像，以及固定业务源码与部署文件。Runtime 两镜像由本次源码重新构建；第三方镜像使用 `deploy/offline-release/images.json` 中固定的平台 digest。部署版本文本在打包时显式渲染为 v0.4.0，每个部署文件都有内部哈希。

`SHA256SUMS`、两份架构 manifest 与顶层 `release-manifest.json` 随 Release 附件提供。报告不含凭据、数据库内容或原始日志。本次交付不表示生产部署完成；现有运行容器未更新。
