# v0.6.1：tkos.world/0.2 读面补齐

补丁版本，在 v0.6.0 之上纳入 world 0.2 读面与 0.1 的等价修复（#94，修 #93）与两份 world-02 部署文档（#91、#92）。**契约、登记、profile 钉定与迁移都没变**：迁移头仍是 0039，`tkos.world/0.2` 仍按 2026-09-30 的[锁版检查点](../world-v02-freeze-checkpoint.md)钉定。tag、Python 包版本、离线包文件名、镜像标签与发布文档统一用 `v0.6.1`／`0.6.1`，镜像标签形如 `<仓库>:v0.6.1-<架构>`。

## 修复

0.2 契约在这几处写「同 0.1」，v0.6.0 的代码没按契约做，本版补齐（#94）：

- **取子对象**（契约第 15.1 节）：`GET /v1/world/objects/{id}/children` 按对象绑定的契约版本分派，0.2 对象只按最新修订的 `parent_ref` 列下级，形状同 0.1，引用给 0.2 的两种形式。v0.6.0 对 0.2 对象返回 409。
- **取对象**（契约第 6 节沿用 0.1）：`business` 新增 `referenced_by`（指向它的跨链关系，含周期目标的 `depends_on`）与 `supersedes`（所读修订取代的上一修订，按修订序号 `version`，第一个修订为 `null`）。0.1 对象的 0.2 视图同样给出这两键。
- **责任人**（契约第 3.3 节同 0.1 第 4 节）：按 `responsible` 属性解析的人须启用、当前在对象所在域持登记给的角色才列出；只改读侧，写侧授权不动。取上下文的「谁负责」在撤角色后随之报缺口。

CLI 的 0.2 Agent 面不加取子对象（锁版契约第 9.3 节与登记 `agent_face` 不含它），要用直接打 HTTP。给天枢的接口清单仓库副本同步了上述变化，见 [接口变化说明](../world-v02-tianshu-interface-changes.md)。

## 交付形式

Release 附件包含 `tkos_memory_service-0.6.1-py3-none-any.whl`、`tkos_memory_service-0.6.1.tar.gz`、amd64／arm64 两套完整离线包（`tkos-ontology-runtime-v0.6.1-linux-<架构>.tar.gz`）、`SHA256SUMS`、两份架构 manifest 与顶层 `release-manifest.json`。每套离线包恰含 Runtime API、Worker、PostgreSQL 17＋pgvector、MinIO Server、MinIO Client 五类镜像（标签 `<仓库>:v0.6.1-<架构>`），以及该版本的完整源码归档；Clark、Nginx、模型服务、凭据、数据库备份与业务数据不在包内。镜像内 `/opt/tkos/docs/` 带齐 Method 0.4、0.5 与 world 0.1、0.2 的控制面安装材料（与 v0.6.0 相同）。前端生产资源随 Python 包交付。GitHub 同时提供标签对应的仓库源码归档。

离线包与 wheel／sdist 由 `d4ed957`（#95 合并提交）构建，与本标签只差两份发布文档与 README；全部构建输入（Dockerfile、pyproject.toml、uv.lock、src、deploy/offline-release）一致，可从本标签复现。第三方镜像 digest 与 `requirements.lock` 与 v0.6.0 相同，三个第三方镜像的本机镜像 ID 也与 v0.6.0 相同。

## 升级及边界

本版没有新迁移，迁移头仍是 **0039**。从 v0.6.0 升级：换离线包的部署文件与镜像，沿用 env（只改五个镜像标签）、MinIO 应用密钥与数据卷重跑 `start-offline.sh`，不会应用任何迁移。从更早版本升级先按 [v0.6.0 发布说明](v0.6.0.md)。发布不自动迁移生产库，不升级旧对象的协议绑定，不创建正式身份或授权。

读侧行为的变化：0.2 对象的取子对象由 409 变为 200；0.2 取对象的 `business` 多两个键；按属性解析的责任人在其不再持角色时不再列出。调用方若按键集合严格校验 `business`，需要接受这两个新键。

给 Agent 侧联调的 world-lab 实例仍跑 v0.5.0（world 0.1），本版不升级它；world-02 实验实例换到本版镜像另行安排，不计作本次发布的一部分。

**尚未验证**：Clark 接线与浏览器端到端、真实业务模型、生产 SSO 与正式身份（[ADR-0008](../adr/0008-enterprise-identity-and-formal-profile-path.md) 待组织裁决）、生产部署与切换、登录后的工作台浏览器复核、本版在 world-lab 或 world-02 实例上的部署、0.2 实验 B 与四种取法的结论。
