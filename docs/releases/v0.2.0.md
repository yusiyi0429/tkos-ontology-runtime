# v0.2.0：首个 Runtime Release

> **已由 v0.2.1 替代。** 本版只收录 AMD64 Runtime API／Worker，不满足完整离线部署组件与双架构要求。请使用 [v0.2.1](v0.2.1.md)。

本版发布已合并的 M1A／M1B 底座、Contract-A A1–A3 和既有交付、记忆兼容能力。Python 包名仍为 `tkos-memory-service`，版本为 `0.2.0`。发布镜像不代表已完成生产切换。

## 发布产物

- `tkos-ontology-runtime-v0.2.0-linux-amd64.tar.gz`：Docker 离线镜像包，包含 `tkos/ontology-runtime:v0.2.0` 与 `tkos/ontology-worker:v0.2.0`。
- `release-manifest.json`：源码提交、架构、镜像 ID、版本标识和容器验证结果。
- `SHA256SUMS`：下载文件的 SHA256 校验清单。
- GitHub 自动提供的 Source code：同一 Tag 的代码、工作台、API 文档及验收驱动。

本包只包含 Runtime 的两个镜像。部署仍需 PostgreSQL／pgvector、版本化 S3／MinIO；MinIO 初始化可用 mc。Clark 与宿主机 Nginx 分别交付。模型、搜索、语音及其他外部服务不包含在镜像包中。该附件只验证 `linux/amd64`；其他架构需另行构建、验证。

## 镜像变更

两种镜像携带相同版本的应用代码、SQL 迁移以及 `/opt/tkos/docs/` 下的 Method Profile、契约和 A2／A3／Method 注册表。Python 和 uv 基础镜像固定 digest，增加 OCI 版本、源码提交和构建时间标识；最终安装仅使用构建阶段的本地 wheel。构建上下文采用允许列表，排除私有配置、测试运行产物和部署目录。API／Worker 继续以非 root 用户运行。

容器启动不会自动迁移、创建身份或安装业务策略。内置 Method Profile 是已验收的实验基线，不能将其中的合成身份和实验标记视为企业正式授权。

## 下载、校验与加载

从 [v0.2.0 Release](https://github.com/yusiyi0429/tkos-ontology-runtime/releases/tag/v0.2.0) 下载全部附件，在同一目录执行：

```bash
sha256sum -c SHA256SUMS
docker load -i tkos-ontology-runtime-v0.2.0-linux-amd64.tar.gz
docker image inspect tkos/ontology-runtime:v0.2.0 --format '{{json .Config.Labels}}'
```

macOS 可用 `shasum -a 256 -c SHA256SUMS`。核对镜像 ID 与 manifest；不要仅依据可变 Tag 判断实际版本。

## 环境初始化与启动

先准备隔离数据环境、备份及私有配置：`runtime.env` 仅含普通应用数据库角色；`migration.env` 中的 `DATABASE_URL` 使用迁移 owner，控制 CLI 另读取 `MIGRATION_DATABASE_URL`。配置文件权限设为 `600`，勿提交。网络名 `tkos-backend` 仅作示例，需由部署方创建并连通数据库与对象存储。

在候选环境核对已有 schema 后，显式应用缺失迁移；本版最新迁移为 `0021_method_foundation.sql`。迁移之外仍须配置应用表权限、域、身份、角色和协议策略，步骤见 [Method 接口说明](../runtime-method-api.md)。

```bash
docker run --rm --network tkos-backend --env-file migration.env \
  tkos/ontology-runtime:v0.2.0 tkos-memory-migrate

docker run -d --name tkos-runtime-api --network tkos-backend \
  --env-file runtime.env -p 127.0.0.1:8030:8010 \
  tkos/ontology-runtime:v0.2.0

docker run -d --name tkos-runtime-worker --network tkos-backend \
  --env-file runtime.env tkos/ontology-worker:v0.2.0
```

Method 控制面输入路径为 `/opt/tkos/docs/contracts/method-profile.json`、`/opt/tkos/docs/contracts/tkos-method-0.1.md` 和 `/opt/tkos/docs/runtime-method-registry.json`。控制 CLI 使用一次性容器及迁移身份；不得将该身份注入 API／Worker。

## 验证与范围

原业务源码的独立验收见 [Method 报告](../runtime-method-acceptance-report.md)：98 项检查、8 个环境门槛及既有能力回归。本次容器验证核对 127 个生产文件和 5 个控制面工件，并在实际 HTTP 上完成 M1A／M1B 两条业务链的 49 项检查、70 次正式动作；另验证 0021 升级及重放、OpenAPI 一致性、未认证拒绝、Worker 任务、重启幂等与对象存储探针。容器以非 root、只读根文件系统运行。

最终镜像核验结果单独记录在发布 manifest；本轮未重跑完整 98 项矩阵及全部 Python 回归，依据是业务源码与既有验收逐字节一致，新增验证聚焦容器交付。

生产身份、Clark 新页面、正式迁移、流量切换及灾难恢复需在目标环境另行完成。数据库、证据对象和 Clark 应用文件分别持久化及备份。根目录仍不提供自动投产 Compose；本次发布不收录尚未完成评审的本地生产切换脚本。
