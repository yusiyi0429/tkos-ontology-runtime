# 对象的生命周期状态由事件日志推导，不存状态枚举

事件是业务世界里唯一的触发源。我们决定不给对象存任何生命周期状态列：每类对象在契约里有一张确定性的状态机，读侧按该对象最近的事件推出 `lifecycle` 并给出推出它的事件；为此承诺与确认事件带阶段（立项 / 交付），外部事件带类别（会议 / 评审 / 交付 / 验收 / 其他）。

## Considered Options

- 存状态枚举并在动作里维护：被否，会出现事件与状态两份真相，且 Agent 写入的状态快照会被误当成触发条件。

## Consequences

- 读投影必须能重放一个对象的事件；按状态筛选需要投影层而不是直接查列。
- 状态机改动是契约改动，随协议版本发布。
- 内核对象表自带的 `lifecycle_status` 列与「生效修订」指针只承担正式内容指针的角色：有门类型建对象为 `draft`、确认时改 `confirmed` 并把生效指针挪到被确认的修订；无门类型一律 `recorded`、生效指针等于最新。它区分正式内容与候选内容，不表达业务生命周期。
