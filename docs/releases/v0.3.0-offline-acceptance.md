## 发现与修复

初始旧模板仅启用版本化和对象锁，没有默认证据保留，业务证据上传实际返回 `EVIDENCE_UNAVAILABLE`。该失败归档未上传。部署模板补充可配置的默认保留期后，以空数据卷重新启动，业务和本体链通过。

验收脚本的宿主机 SQL/S3 访问受 Docker Desktop 内部网络限制，因此仅验收环境额外开放回环端口与网络接线；发布包未包含这些覆盖。令牌文件恢复为看板要求的 0600 后，使用新合成身份重跑，不采用失败结果。最终再次用原始发布 Compose 验证健康。

## 发布物与来源

每个离线包恰好包含 Runtime API、Worker、PostgreSQL 17/pgvector、MinIO Server、MinIO Client 五镜像，以及固定业务源码和部署文件。Runtime 两镜像均由 v0.3.0 重新构建；第三方镜像使用固定平台 digest，不以旧 Runtime 镜像替代。

`source_ref` 标识业务源码，`deployment_source_ref` 标识部署修复。部署版本文本在打包时显式渲染为 v0.3.0，每个部署文件都有内部哈希。标签内 README 反映最初 Python 包发布时状态，补充离线安装与构建以本次 Release 附件 `README-v0.3.0.md` 为准。

完整机器报告、架构 manifest、复现脚本和 SHA256SUMS 随 [v0.3.0 Release](https://github.com/yusiyi0429/tkos-ontology-runtime/releases/tag/v0.3.0) 提供。报告不含凭据、数据库内容或原始日志。现有五个运行容器保持不变；本次交付不表示生产部署完成。
